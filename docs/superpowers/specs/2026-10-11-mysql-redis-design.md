# MySQL + Redis 会话设计

现有 MySQL `sessions`、`messages` 是唯一持久化来源，保留完整历史与会话版本号。Redis 仅缓存 Agent 所需的最近 100 条消息，键为 `session:{id}:messages`，默认 TTL 1800 秒。缓存项包含 MySQL 会话版本号；每次继续会话先从 MySQL 读取版本，仅在版本一致时使用缓存。缓存未命中、过期、损坏或 Redis 不可用时，从 MySQL 重建上下文。

成功提交一轮问答后，删除该会话缓存；下次请求按已提交的消息重新填充。删除会话后也删除缓存。缓存操作必须在 MySQL 事务之外进行，失败不能改变聊天与删除结果。流式和普通聊天共用 `SessionService`，因此遵守同一规则。会话详情始终查 MySQL，返回完整历史。

本阶段不建立尚无使用入口的用户、文档、评测空表。现有应用为单用户，尚无鉴权、上传和评测入库业务；需要这些功能时再设计对应表与迁移。部署通过 Docker Compose 提供 Redis，`REDIS_URL` 未设置时禁用缓存，方便本地仅用 MySQL 运行。

验证：单元测试覆盖命中、未命中、版本变化、Redis 故障及删除失效；API 测试覆盖普通和流式聊天；可选的真实 Redis 联调检查 TTL。既有 MySQL 持久化测试继续保留。
