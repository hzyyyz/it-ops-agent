# 总计划缺口收尾实施计划

> 本计划在现有脏工作区内实施，不批量提交或重置已有改动。按测试先行，每个任务独立验证。

1. 健康检查与知识上传兼容入口：测试存活/依赖状态以及 multipart 上传的文件校验、同步和失败语义；实现 API；更新 README。
2. 鉴权：按本地管理员凭据方案先写未授权/授权及前端会话测试，再保护所有读写 API；更新 Web 和 Streamlit 客户端。若用户选择多用户，先补会话归属和数据迁移设计。
3. MySQL 元数据：先验证新表结构与重复初始化，再实现 `users/documents/evaluation_results` 模型及文件/评测记录写入；不破坏原有会话。
4. 效果验证：增加可重复的 RAG 比较命令与启用状态输出，运行当前环境可执行的评测；明确人工评估边界。
5. 部署与终验：完整 pytest、JavaScript 语法、静态页面检查、Docker 可用性及 Compose 验证；逐项更新 README 和收尾结论。
