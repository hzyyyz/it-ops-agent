# 设备健康报告工作流设计

报告请求由轻量意图判断路由至独立 LangGraph；普通请求仍走现有 ReAct Agent，保留 SSE 分块输出。报告图中的节点依次为 `resolve_identity`（解析或获取员工号）、`resolve_month`（解析或获取月份）、`lookup_asset`（读取台账）、`collect_status`（提取台账中的运行与维保状态）、`generate_report`（基于已查到的记录调用报告模型）、`reset_state`。找不到记录时跳过模型，回复明确的缺失数据说明，再进入复位节点。

报告中只把台账的历史运行状态称为员工设备状况，不把 MCP 容器指标冒充个人电脑实时状态。当前 `get_employee_id` 为模拟员工号，未指定员工号时报告须标明其演示性质。用户明确给出的月份优先；未提供月份时取当前月，缺失数据不能回退成其他月份的报告。报告图的状态仅在单次请求中存在，正常结束和异常结束都清理报告上下文。

工具、模型和报告阶段继续使用现有 `trace_id`，只记录阶段、状态、耗时、异常类型及数据是否存在，不写入员工记录或报告正文。测试使用虚假取数与模型，覆盖正常请求路由、报告节点顺序、缺失记录不调用模型、显式参数、复位和 SSE 输出。
