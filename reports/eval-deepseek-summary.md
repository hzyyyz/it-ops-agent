# DeepSeek Agent 评测记录（2026-10-10）

运行方式：`CHAT_MODEL_NAME=deepseek-flash python -m evaluation.runner --mode agent --output reports/eval-deepseek-agent.json`。模型端点为 `https://api.deepseek.com`，密钥从项目 `.env` 的 `DEEPSEEK_API_KEY` 读取。评测前启动了本地 MCP 监控服务，并实际调用 CPU 工具验证连接。

完整逐题结果保存在本地 `reports/eval-deepseek-agent.json`，因可能含模型回答和本机信息而不提交到公开仓库。评测集包含工具调用、RAG、混合任务、健康报告、非 IT 问题各 10 题。50 题均得到非空回答，Agent 层无未捕获异常。

| 指标 | 结果 | 解释 |
| --- | ---: | --- |
| 预期工具召回 | 76/76（100%） | 每题标注的必需工具都被选择 |
| 工具选择精度 | 76/98（77.6%） | 按每题不同工具名统计；14 题使用了额外工具 |
| 任务成功规则代理值 | 50/50（100%） | 仅检查必需工具被选中且回答非空，**不代表事实正确或任务完成** |
| 首字延迟 | 中位数 1.44 秒，P95 14.30 秒 | 包含 Agent 初始化时间 |
| 总延迟 | 中位数 8.47 秒，P95 21.80 秒 | 单次本机运行，受网络和工具响应影响 |
| 统计到的 token | 输入 263,883；输出 41,616 | 来自 Agent 图消息；RAG 工具内部模型调用可能未计入 |

按题型检查额外工具调用：工具题 1/10、RAG 题 0/10、混合题 5/10、健康报告题 8/10、非 IT 题 0/10。健康报告是最需要优化工具规划的场景；例如 `report-07` 已指定工号和月份，Agent 仍调用了获取当前工号和月份的工具。

资产台账 `data/external/records.csv` 的最新月份为 **2026-08**，没有 2026-10 记录。因此 `report-01`、`report-02`、`report-03`、`report-06`、`report-08`、`report-10` 这 6 道“本月”题无法从台账生成完整量化报告。多数回答明确说明数据缺失；`report-01` 另外使用 MCP 服务所在主机的实时指标生成运行状态分析，不能把它理解为员工设备资产数据。这里的 100% 规则代理值明显高估了实际报告完成度。

这次 Agent 评测没有对最终回答做人工事实核验，也没有给报告完整度、引用依据或工具结果真实性打分。独立的离线检索对比仍见 `eval-baseline.json` 与 `eval-advanced.json`；它们不包含在线改写或本地重排模型效果。下一轮应为健康报告加入“有记录/无记录”的预期结果和字段级校验，并增加能区分两种检索路径的困难样例。
